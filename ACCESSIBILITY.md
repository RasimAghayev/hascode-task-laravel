# Accessibility Statement

## Commitment

We are committed to making this project accessible to everyone, including people
with disabilities. We strive to conform to the Web Content Accessibility
Guidelines (WCAG) 2.1 Level AA and continuously work to improve the
accessibility of our software.

## Supported Environments

We test accessibility in the following environments:

| Environment | Status |
|-------------|--------|
| Desktop browsers (Chrome, Firefox, Safari, Edge) | Tested |
| Screen readers (NVDA, JAWS, VoiceOver) | Tested |
| Keyboard-only navigation | Tested |
| High contrast mode | Tested |
| Zoom up to 200% | Tested |
| Mobile browsers (iOS Safari, Android Chrome) | Tested |

## Known Limitations

We are aware of the following accessibility limitations:

- Some third-party dependencies may not fully meet accessibility standards
- Legacy code areas may have incomplete keyboard support or ARIA attributes
- Automated tooling may not catch all semantic HTML issues

We are actively working to address these limitations in future releases.

## Reporting Accessibility Barriers

If you encounter an accessibility barrier while using this project, please let
us know:

1. **Open an issue** using the "Accessibility" label (if available) or
   "Bug Report" template
2. **Describe the barrier** you encountered, including:
   - The page, component, or feature affected
   - The assistive technology or configuration used
   - Steps to reproduce the issue
   - Expected vs. actual behavior
3. **We will acknowledge** your report within 7 days and prioritize a fix
   based on severity and impact.

## Feedback

We welcome feedback on how we can improve accessibility. Contributions that
enhance accessibility (better semantics, improved keyboard navigation, ARIA
fixes, etc.) are especially appreciated.
